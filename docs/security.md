# 安全文档 — 妥协清单

本 API 面向可信私有环境，以下均为当前方案的有意取舍。

| # | 项目 | 现状 | 影响 |
|---|------|------|------|
| 1 | 身份认证 | 无。`user` 为自报字符串 | 任何人可冒充任意用户，读写其全部数据 |
| 2 | 传输加密 | 不强制 HTTPS | 参数（含文件内容）明文过网 |
| 3 | GET 副作用 | 全部写操作经 GET | 浏览器预取、爬虫、代理缓存可意外触发写入/删除 |
| 4 | 参数入 URL | `content`、`tags` 经 Query String 传递 | 内容留存于浏览器历史、服务器与中间代理日志；受 URL 长度上限约束（约 2–8 KB） |
| 5 | CORS | `Access-Control-Allow-Origin: *` | 任意网页均可跨域调用本 API |
| 6 | 速率限制 | 无 | 可被高频请求耗尽资源 |
| 7 | 存储配额 | 无 | 单用户可写满磁盘 |
| 8 | 输入净化 | `name`/`content`/`tags` 原样存储与返回 | 客户端渲染时需自行转义，防 XSS 归客户端 |

## 说明

- 用户隔离仅依赖 `user` 参数，无任何凭据校验，等同无隔离。
- 不存在路径穿越：目录仅一层文件夹，`name` 始终按字面名匹配，不解析 `..`、`/` 等路径语义。
- SQL 注入不适用：全部查询参数化。
- 删除操作无回收站，`/del` 即永久删除。
- 数据存储为单文件 SQLite（`data.db`），无备份机制。
